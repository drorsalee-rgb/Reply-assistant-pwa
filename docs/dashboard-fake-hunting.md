# מפרט: טאב "הזמת פייקים" בדשבורד

מסמך לצוות הדשבורד (`torino-social.web.app`). כל הנתונים כבר יושבים ב-Firestore
של פרויקט `torino-social` — אין צורך בשירות חדש או ב-API חיצוני. צריך רק לקרוא
ולהצליב.

המטרה: שתי טבלאות — **מי רשום**, ו**מי פתח כל התראה**.

---

## אזהרת פרטיות — לקרוא לפני הכול

האוסף `fake-hunt-optins` מכיל **מספרי טלפון ושמות פרטיים** של מתנדבים,
ו-`fake-hunt-selections` מאפשר לקשר בין אדם מסוים לפעולה שלו.

- הנתונים האלה חייבים להישאר **מאחורי הזדהות בדשבורד**.
- אין להוסיף אותם לכללי קריאה ציבוריים ב-Firestore. שימו לב ש-`social-reactions`
  הוא ציבורי (ה-PWA קורא אותו ישירות מהדפדפן) — **אל תחילו את אותו כלל** על
  האוספים כאן.
- אין להוציא מספרי טלפון ל-URL, לפרמטרים או ללוגים.

---

## האוספים

### 1. `fake-hunt-optins` — מי רשום

מסמך לכל אדם. מזהה המסמך: `whatsapp:+9725XXXXXXXX`.

| שדה | טיפוס | הערות |
|---|---|---|
| `phone` | string | בפורמט E.164, למשל `+972547554469` |
| `firstName` | string | שם פרטי מוואטסאפ. **עשוי להיעדר** — לא כולם מגדירים שם תצוגה |
| `active` | boolean | `false` = האדם שלח "הסר". להציג כ"הוסר", לא למחוק מהטבלה |
| `networks` | array\<string\> | `x`, `facebook`, `instagram`, `tiktok`, `youtube`, `linkedin` |
| `platform` | string | כרגע תמיד `whatsapp` |
| `joinedAt` | timestamp | הרשמה ראשונה |
| `updatedAt` | timestamp | שינוי אחרון בהעדפות |

**שתי מלכודות:**

1. `networks` **ריק או חסר** אין פירושו "שום רשת" — פירושו ברירת המחדל:
   `x, facebook, instagram, tiktok`. להציג "ברירת מחדל" ולא תא ריק.
   יוטיוב ולינקדאין אינם בברירת המחדל בכוונה.
2. `active: false` הוא מצב לגיטימי שאפשר לחזור ממנו — אדם שהוסר ונרשם שוב
   מקבל `active: true` על אותו מסמך.

### 2. `fake-hunt-selections` — למי נשלחה כל התראה

מסמך לכל שליחה בודדת לאדם בודד.

| שדה | טיפוס | הערות |
|---|---|---|
| `phone` | string | הנמען |
| `messageId` | string | מזהה ההתראה (מקביל ל-`fake-hunting-messages`) |
| `variant` | integer | **מספר ה"משבצת" של הנמען** — קריטי, ראו הצלבה למטה |
| `platform` | string | `whatsapp` |
| `flow` | string | `fake-hunting` |
| `selectedAt` | timestamp | מועד השליחה |

**שורות ישנות:** מסמכים מלפני המעבר לוואטסאפ מכילים `documentId` במקום
`messageId`, ו-`phone` שהוא UUID של סיגנל ולא מספר טלפון. אפשר לסנן אותם
לפי היעדר `messageId`.

### 3. `pwa-stats` — כמה נפתח

מזהה המסמך: `debunk:<messageId>` (שימו לב לקידומת — מסמכים ללא קידומת שייכים
ל-PWA הרגיל).

| שדה | הערות |
|---|---|
| `opens` | סך פתיחות, כולל חוזרות |
| `uniqueOpens` | מספר מכשירים שונים שפתחו |
| `copyOpen` | סך לחיצות על "העתק ופתח" |
| `uniqueCopyOpen` | מספר מכשירים שונים שלחצו |
| `lastEventAt` | פעילות אחרונה |

**תת-אוסף `recipients`** — כאן נמצא הייחוס האישי. מזהה המסמך הוא מספר
המשבצת (`"0"`, `"1"`, …), והשדות הם `opens`, `copyOpen`, `lastEventAt`.

```
pwa-stats/debunk:3T0kxSjnFNxsdURZlsIn/recipients/1  →  { opens: 1 }
```

### 4. `fake-hunting-messages` — תוכן ההתראה

בבעלות שרת מציאת הפייקים. שימושי לתצוגה בלבד: `text` (הטענה + ההפרכה)
ו-`post_url` (הפוסט שמגיבים עליו, יכול להיות `null`).

## ההצלבה — איך יודעים מי פתח

לכל נמען נשלח קישור ייחודי עם אינדקס משלו:

```
https://yoriki-500811.web.app/debunk/?message_id=<messageId>&v=<variant>
```

ה-`v` הזה הוא אותו `variant` שנשמר ב-`fake-hunt-selections`, והוא גם מזהה
המסמך בתת-האוסף `recipients`. מכאן:

```
fake-hunt-selections[messageId, variant].phone
      ↕  variant
pwa-stats/debunk:<messageId>/recipients/<variant>.opens
```

כלומר: **אדם מסוים פתח התראה מסוימת** אם קיים מסמך `recipients/<variant>`
עם `opens > 0`, כאשר אותו `variant` משויך לטלפון שלו באותה התראה.

הערה: הייחוס הוא לקישור, לא לזהות מאומתת. אם מישהו מעביר את הקישור שלו הלאה,
הפתיחה תיזקף לו. זה מספיק טוב למדידת מעורבות, ולא צריך להתייחס לזה כראיה.

## שתי הטבלאות המבוקשות

### טבלה א' — מי רשום

מקור: `fake-hunt-optins`, מוצלב עם `fake-hunt-selections` לפי `phone`.

| עמודה | חישוב |
|---|---|
| שם | `firstName`, או "—" |
| טלפון | `phone` |
| רשתות | `networks`, או "ברירת מחדל" אם ריק. אם `active=false` → "הוסר" |
| תאריך הצטרפות | `joinedAt` |
| נשלחו | מספר מסמכי `fake-hunt-selections` עם ה-`phone` הזה |
| פתח | מתוכם, כמה עם `recipients/<variant>.opens > 0` |
| הגיב | מתוכם, כמה עם `recipients/<variant>.copyOpen > 0` |

### טבלה ב' — לפי התראה

מקור: `fake-hunt-selections` מקובץ לפי `messageId`.

| עמודה | חישוב |
|---|---|
| התראה | `messageId` (כדאי לקשר ל-`fake-hunting-messages` ולהציג את תחילת הטענה) |
| מתי | `selectedAt` |
| נשלחו | מספר הנמענים |
| פתחו / הגיבו | ספירה לפי תת-האוסף `recipients` |
| מי פתח | רשימת השמות של הנמענים שפתחו |

## הערות שיחסכו באגים

- **אזור זמן:** כל ה-timestamps ב-UTC. הדשבורד צריך להציג בשעון ישראל.
- **היסטוריה ריקה:** הייחוס האישי הופעל ב-23/08/2026. התראות מלפני כן יציגו
  0 פתיחות — זה נכון טכנית ומטעה חזותית, אז כדאי לסמן אותן.
- **משבצת כפולה:** בבדיקות נשלחה אותה התראה כמה פעמים, מה שיצר כמה שורות
  `fake-hunt-selections` על אותו `messageId` + `variant`. בפרודקשן זה לא קורה
  (יש דדופליקציה לפי `message_id`), אבל בנתונים הקיימים כדאי לקחת את השורה
  האחרונה לפי `selectedAt`.
- **גודל המאגר:** כרגע יחידות בודדות של נרשמים. אין צורך באגרגציה מראש —
  קריאה ישירה מספיקה. אם המאגר גדל מעבר לכמה אלפים, כדאי לשקול מונה מצטבר
  במקום ספירת מסמכים.
- **שאילתת collection group:** כדי לאסוף את כל תת-האוספים `recipients` בבת אחת
  צריך שאילתת collection group על `recipients` (`allDescendants: true`).
